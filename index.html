MFA для всего периметра. Один контейнер. Без облака.

Ligament закрывает Windows-логон и RDP, корпоративный Wi-Fi и VPN по RADIUS, единый вход в веб-сервисы через OIDC, SAML и Kerberos, филиалы, бастион, экстренную помощь и шлюз уведомлений. База, ключи и аудит остаются на ваших серверах — работает и без интернета.

Возможности

Что умеет Ligament

14 модулей корпоративной защиты периметра в едином Docker-контейнере.

01
СтабильноТребует настройки

Windows Logon & RDP 2FA (Credential Provider)

  • Нативная плитка LogonUI на Windows 10/11 и Server 2016–2025.
  • Auto-Logon после подтверждения на телефоне: вход в Windows без дополнительного клика и Enter.
  • Number matching против push-бомбинга и утомления (push fatigue).
  • UAC elevation 2FA — обязательный второй фактор при повышении прав администратора.
  • Over-the-shoulder подтверждение: запрос уходит на телефон администратора, а не оператора за клавиатурой.
  • FIDO2 / Passkeys / YubiKey прямо на экране входа через динамический QR-код.
  • Fail-Open / Fail-Close политики и аварийный break-glass белый список.
  • Тихая установка единым MSI (с параметром SERVERURL) и централизованное развертывание через GPO/ADMX.
2FA входа в MSI по умолчанию выключена и активируется политикой RDP2FAEnabled=1 / Console2FAEnabled=1. UAC-сценарий требует credentialed-UAC.

Стабильно

RADIUS-сервер

  • Поддержка протоколов PAP, EAP-TTLS/PAP, PEAP/MS-CHAPv2 и RADIUS Accounting.
  • Совместимость с MikroTik RouterOS, Cisco ASA/IOS, Fortinet FortiGate, Ubiquiti UniFi, Check Point, Huawei, Keenetic.
  • Корпоративный Wi-Fi 802.1X (WPA2/WPA3-Enterprise) и VPN (L2TP/IPsec, SSTP, OpenVPN, IKEv2, WireGuard, PPPoE).
  • Push Holding сессии: удержание RADIUS-запроса на время подтверждения вторым фактором.
  • Корректная обработка UDP-ретрансмитов по RFC 5080 (исключение дублирования запросов).
  • Принудительное завершение сессии по RFC 5176 CoA-Disconnect и kick-sta фолбэк для UniFi.
  • Device Trust Window (лицензируется), управление VSA-атрибутами и синхронизация MFA с Relay.

СтабильноDemo / Коммерция

SSO: OIDC + SAML IdP и MFA-прокси

  • Собственный провайдер OpenID Connect без необходимости развертывать Keycloak.
  • SAML 2.0 Identity Provider с поддержкой RSA-SHA256 подписей и HTTP POST-binding.
  • Forward-auth прокси (nginx auth_request / Traefik forwardAuth) — MFA любому сервису без изменения кода (заголовки X-Auth-User, X-Auth-Role).
  • Соответствие стандартам: /.well-known/openid-configuration, JWKS RS256, PKCE (RFC 7636).
  • Launchpad-портал корпоративных приложений и IdP-initiated SAML навигация.
  • Готовые интеграции: Nextcloud, GitLab, 1С:Предприятие, Proxmox VE, Grafana, Portainer, Zabbix, BookStack.

Проверено в продеТребует настройки

Kerberos SSO — «Вход через Windows»

  • Беспарольный вход с доменного компьютера без ввода логина и пароля.
  • Браузер предъявляет Kerberos-тикет (SPNEGO), сервер верифицирует его через keytab службы.
  • Сотрудник проходит только второй фактор (passkey, push или одноразовый код).
  • Бесшовная первая ступень для входа в OIDC-приложения и мост browser_sso для SAML.
  • Автоматическое заведение доменных имен через LDAP-развязку (DomainAccountName).
  • Строгая валидация msDS-SupportedEncryptionTypes и проверка целостности билетов.
Контур проверен в продакшене 12.10.2026 (ядро ≥ v0.8.179). Требует настройки Service Principal Name (SPN) и выгрузки keytab.

Филиалы: Ligament Relay

  • Компактные локальные агенты для удаленных офисов, филиалов и изолированных DMZ.
  • Локальный кэш аутентификации: бесперебойный вход сотрудников при обрыве WAN-канала.
  • Постоянный шифрованный WebSocket-туннель с автоматической фоновой синхронизацией.
  • «Слепая труба» для бастиона: трафик Web-SSH и RDP проходит транзитом, узел Relay не читает сессию.
  • Минимальные системные требования, поддержка Linux (Docker, binary) и Windows Server.

  • Доставка кодов через Email (SMTP), SMS-шлюзы и голосовой вызов TTS для пользователей без смартфонов.

Удалённый доступ к машинам и endpoint-консоль

  • Маршрутизация direct, через agent, через Relay или через Terminal Server с inline passkey-MFA.
  • Уведомления об удаленном подключении с фиксацией инициатора, цели, IP, часового пояса и ID сессии.

SOS-помощь: WebRTC-консоль

  • Кнопка запроса экстренной помощи прямо на экране входа Windows (до логина в систему).

  • Полная независимость от облачных утилит класса AnyDesk и TeamViewer.

Device Posture и корпоративное управление клиентами

  • Windows: контроль статуса BitLocker (manage-bde), Windows Defender и Windows Firewall (netsh).
  • macOS: проверка FileVault (fdesetup), Gatekeeper (spctl), macOS Firewall и Touch ID.
  • Android и iOS: автоматическая детекция Root / Jailbreak и целостности среды выполнения.
  • Контроль задержки доставки push-канала (SLA телеметрия) и отображение статуса в кабинете /me/devices.
  • Приоритетные уведомления: Full-Screen Intent (Android) и Time-Sensitive Alerts (iOS).
  • Единый пакет MSI: клиент + DLL Credential Provider + сторожевая служба Ligament2FAService (LocalSystem).
  • Шаблоны Windows GPO/ADMX и Apple macOS MDM: принудительный URL, запрет закрытия (AllowExit=0).

Безопасность, роли, мониторинг, эксплуатация

  • Argon2id для хеширования паролей, AES-256-GCM с AAD для секретов в БД, Ed25519 для лицензий.
  • Встроенный файрвол с поддержкой CIDR-масок и автоматическая блокировка перебора (fail2ban).

  • Метрики Prometheus /metrics, SIEM-коннектор (CEF / LEEF) и вебхуки событий ИБ.
  • Неизменяемый журнал аудита с разделением внешнего и внутреннего IP (офис vs удаленка) и печатный отчет по инциденту.

Интеграция с СКУД (PACS) — ранний модуль

  • Физический доступ как фактор ИБ: подключение СКУД как источника событий реального присутствия сотрудника.
  • Реестр драйверов в коде ядра: Болид (ИСО «Орион Про» через IntegrServ 2.0.1 JSON-RPC и нативный MS SQL адаптер), Sigur, PERCo (PERCo-Web), Parsec (ParsecNET), RusGuard.
  • Автоматическая привязка карты к сотруднику по точно совпавшему нормализованному ФИО (до 100 000 субъектов).
  • Фоновый постраничный импорт справочника (по 500 записей), устойчивый к перезапускам сервера.
  • Журнал проходов с настраиваемым сроком хранения (по умолчанию 90 дней) и фиксацией госномеров автотранспорта.
  • Zero-Trust проверка присутствия для RDP: доступ к критическому серверу разрешен только при физическом нахождении сотрудника во внутренней зоне предприятия.
Модуль СКУД находится на этапе стендовой приёмки. Продаётся строго по отдельной лицензии (не входит в пакетные опции «all»/*). Условия поставки — по индивидуальному запросу.

Честно: где Ligament иной или проще

Международный корпоративный Wi-Fi сегмент уходит в сложные сертификатные цепочки EAP-TLS. Ligament сознательно сохраняет проверенный парольный EAP-TTLS/PEAP с живым push-подтверждением: это в разы проще, дешевле и надежнее в эксплуатации для малых и средних корпоративных сетей. Часть модулей (SSO, бастион, Relay, СКУД) требует активной лицензии. UAC-сценарий требует credentialed-UAC и соответствующей настройки Windows. 2FA входа в MSI выключена по умолчанию и включается политикой. СКУД является ранним модулем.

Вопросы и ответы

Часто задаваемые вопросы

Технические разъяснения для системных администраторов и инженеров ИБ.

Нужен ли интернет для работы Ligament?
Нет. Работа в полностью изолированной среде (air-gapped) — штатный режим Ligament. Все компоненты, база данных, секреты, ключи шифрования и проверка лицензии функционируют локально без внешних запросов к облаку.
Что произойдет после окончания 30 дней Demo-периода?
Сервер автоматически и мягко перейдет в бесплатную редакцию Free (до 5 пользователей). Существующие входы не блокируются аварийно, система сохраняет стабильность, а администратор может ввести коммерческий ключ в любой момент.
Можно ли запретить сотруднику самостоятельно отключать 2FA?
Да. В системе действует принудительная политика двухфакторной аутентификации: пользователь не может удалить свой единственный зарегистрированный фактор в кабинете самообслуживания.
Как не заблокировать доступ к Windows при аварии сети?
Ligament Credential Provider поддерживает настраиваемые политики Fail-Open (разрешить вход по локальному паролю при недоступности сервера) или Fail-Close, а также список аварийных учетных записей (Break-Glass Whitelist).
Работают ли клиентские приложения с Astra Linux, РЕД ОС и Альт?
Да. Клиент Ligament Authenticator официально собирается в форматах .deb, .rpm и универсальном .tar.gz, проверен на Astra Linux 1.7/CE, РЕД ОС 7.3/8, Альт Рабочая станция p9/p10, Ubuntu, Debian и RHEL.
Можно ли использовать Ligament только для веб-сервисов?
Да. Благодаря собственному IdP (OIDC и SAML) и forward-auth прокси вы можете защитить внутренние веб-порталы (Nextcloud, GitLab, 1C, Zabbix), даже если у вас не используется RADIUS или Windows Credential Provider.
Кто имеет доступ к видеозаписям сессий SOS-помощи?
Медиа-трафик при удаленной помощи передается по протоколу WebRTC peer-to-peer (P2P) с шифрованием DTLS-SRTP напрямую между оператором и пользователем. Сервер участвует только в установлении сессии и аудите, не расшифровывая экран.
Почему Ligament использует парольный EAP-TTLS/PEAP вместо EAP-TLS?
Международный корпоративный Wi-Fi сегмент уходит в сложные сертификатные цепочки EAP-TLS. Ligament сознательно сохраняет проверенный парольный EAP-TTLS/PEAP с живым push-подтверждением: это в разы проще, дешевле и надежнее в эксплуатации для малых и средних корпоративных сетей.
Как мигрировать с зарубежных решений (privacyIDEA, Cisco Duo)?
Ligament поддерживает стандартные протоколы RADIUS, OIDC и LDAP. Вы можете переключить точки аутентификации на адрес сервера Ligament за считанные минуты без изменения настроек сетевого оборудования.
Требуется ли устанавливать локального агента для Kerberos-входа?
Нет. Вход «Вход через Windows» работает через стандартный механизм браузера SPNEGO/Kerberos. Агент на рабочей станции не требуется — достаточно настройки Service Principal Name (SPN) и выгрузки keytab на сервер Ligament.
