Honest Differences: Where Ligament is Different or Simpler

Global enterprise Wi-Fi markets are migrating towards complex certificate-based EAP-TLS architectures (SecureW2, Keytos, RADIUSaaS). Ligament deliberately maintains password-based EAP-TTLS/PEAP with live mobile push confirmation — vastly easier, more cost-effective, and robust to operate for small and mid-sized networks. Certain advanced modules (SSO, Bastion, Relay, PACS) require an active license. Windows UAC elevation requires credentialed-UAC policy. 2FA on Windows logon is disabled by default upon MSI installation and enabled via GPO policy. PACS is an early laboratory module.

Deployment

Ready in 2 Minutes

No build tools or compiler required — pre-built Docker containers and native OS installers.

One-command installation script (recommended): 
mkdir -p ligament && cd ligament
curl -fsSL https://raw.githubusercontent.com/aligorov/ligament/main/install.sh -o install.sh
chmod +x install.sh && ./install.sh

The installer validates Docker availability, verifies TCP ports 80/8080 and UDP ports 1812/1813 are free, safely generates and saves the PostgreSQL database secret into .env (with chmod 600 permissions), waits for health endpoint readiness, and generates admin_password.txt and admin_recovery_codes.txt.

FAQ

Frequently Asked Questions

Direct technical answers for system administrators and security officers.

Does Ligament require internet connectivity to operate?
No. Completely isolated (air-gapped) on-premise operation is the primary design pattern of Ligament. All databases, cryptography, logs, and license validation operate 100% locally with zero phone-home calls.
What happens when the 30-day Enterprise Demo expires?
The server gracefully and automatically transitions into the Free edition (up to 5 users). Active user sign-ins are never abruptly locked out, and the administrator can activate a license key at any time.
Can administrators prevent users from disabling their 2FA?
Yes. Ligament enforces a mandatory 2FA security policy: users are strictly prohibited from removing their last enrolled authentication factor in the self-service portal.
How does Ligament prevent Windows lockouts during network failure?
The Ligament Windows Credential Provider supports configurable Fail-Open (fallback to Windows password if core is unreachable) and Fail-Close modes, alongside an emergency break-glass bypass whitelist.
Does the client support Russian Enterprise Linux distributions?
Yes. Ligament Authenticator is packaged as .deb, .rpm, and universal .tar.gz, verified across Astra Linux 1.7/CE, RED OS 7.3/8, Alt Linux p9/p10, Ubuntu, Debian, and RHEL/Rocky.
Can Ligament be deployed solely for internal web application SSO?
Yes. With native OpenID Connect, SAML 2.0 IdP, and forward-auth proxying, you can protect internal web apps (GitLab, Nextcloud, 1C, Proxmox) without configuring RADIUS or Windows logon modules.
Who can view remote SOS assistance session streams?
Assistance sessions transmit media via peer-to-peer (P2P) WebRTC encrypted with DTLS-SRTP directly between user and operator. The server performs only signaling and audit recording, with no access to stream data.
Why does Ligament support password-based EAP-TTLS/PEAP instead of EAP-TLS?
While large global enterprises often use certificate-heavy EAP-TLS, Ligament deliberately retains password-based EAP-TTLS/PEAP combined with instant mobile push. This pattern is vastly simpler and more economical to maintain for small-to-mid enterprise networks.
How easy is it to migrate from privacyIDEA or Cisco Duo?
Because Ligament adheres to standard RADIUS, OIDC, and LDAP RFCs, you can migrate network authenticators and web applications to Ligament in minutes without altering hardware switches or VPN controllers.
Is a local workstation agent required for Kerberos SSO?
No. The 'Windows Logon' SSO feature leverages native browser SPNEGO/Kerberos ticket negotiation. No desktop agent is needed—only standard Active Directory SPN binding and service keytab export.
